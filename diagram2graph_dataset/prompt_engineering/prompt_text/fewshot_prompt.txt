TASK + OUTPUT RULES (follow exactly)
You are a diagram-to-graph extractor. Given a flowchart/diagram image, output ONLY valid Turtle using the diagram2graph (d2g) vocabulary.

1) Prefixes (only these two)
@prefix d2g:  <http://example.org/diagram2graph#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .

2) Identifiers (IRIs)
- Nodes: <http://example.org/diagram/diagram/node/{N}>
- Edges: <http://example.org/diagram/diagram/edge/{E}>
- Node numbering: visual reading order (top→bottom, left→right).
- Edge IDs: ST where S=source node ID and T=target node ID (e.g., edge/12).

3) Nodes (one per readable shape)
<…/node/N> a d2g:Node, d2g:{Start|Process|Decision|Delay|Terminator} ;
    rdfs:label "exact text from the shape" ;
    d2g:shape d2g:{TartEvent|TaK|Gateway|Delay|EndEvent} .
Required shape mapping (use these exact tokens—even if misspelled):
- Start/Begin → d2g:TartEvent
- End/Stop   → d2g:EndEvent
- Rectangle  → d2g:TaK
- Diamond    → d2g:Gateway
- Delay      → d2g:Delay

4) Edges (one resource per arrow)
<…/edge/ST> a d2g:Edge, d2g:{Solid|Dashed} ;
    d2g:source <…/node/S> ;
    d2g:target <…/node/T> ;
    d2g:relationshipType d2g:{Follows|Branches} ;
    [optional] d2g:relationshipValue "arrow label (Yes/No/etc.)" .
Rules:
- If source node is Decision → relationshipType=d2g:Branches; include relationshipValue when text exists.
- Otherwise → relationshipType=d2g:Follows.
- Set line style precisely: d2g:Solid for solid lines; d2g:Dashed for dashed/dotted.

5) Convenience node-to-node triples (also required)
- Follows:  <…/node/S> d2g:follows  <…/node/T> .
- Branches: <…/node/S> d2g:branches <…/node/T> .

6) Output rules
- Output Turtle only; no explanations or extra text.
- Group by subject; one triple per line; end every line with a period.
- All edge sources/targets must reference existing node IRIs.
- Use only d2g and rdfs prefixes; tokens EXACTLY as specified above.
